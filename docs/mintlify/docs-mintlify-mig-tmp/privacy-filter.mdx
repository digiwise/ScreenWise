ScreenWise can redact personal information from captured text before returning
search results to local clients. Redaction runs on the same machine as the
recorder and never sends captured text to a hosted service.

For the complete data-flow model, see [privacy data flow](/privacy-data-flow).

## Local redaction paths

| path | availability | behavior |
| --- | --- | --- |
| deterministic regex | always available | redacts common credentials, contact details, account numbers, and other structured secrets |
| ONNX text model | available after explicit provisioning and checksum verification | adds context-sensitive text classification without network access |

If the ONNX files are absent or fail verification, model redaction remains
unavailable and ScreenWise uses the deterministic regex path. The application
does not download, repair, or update model files.

## Provision the ONNX model

Use a separate download tool on a machine where Internet access is permitted,
then place the documented model files in ScreenWise's local model directory.
Verify every file against the SHA-256 manifest shown by the application's model
status/setup guidance before enabling ONNX redaction. A missing or mismatched
file is rejected locally.

## Use the filter

- In local chat, enable the privacy shield before requesting recorder context.
- Enable privacy filtering before recording so stored text is already redacted
  when it is later returned by the authenticated local API.

Example:

```text
Before: email person@example.com and use token sk-example
After:  email [EMAIL] and use token [SECRET]
```

## Boundaries

- Redaction is local and text-only on the supported Windows path.
- No hosted enclave, remote model endpoint, or product account is involved.
- Regex and model output are defense-in-depth, not a guarantee. Configure
  application, window, and URL exclusions so highly sensitive content is not
  captured in the first place.
