The `screenpipe-mcp` package is a separate local client for ScreenWise's
authenticated API. ScreenWise does not download it, install it into another
application, edit third-party configuration, or discover credentials through a
package manager.

## provision the package

Build the MCP package from this repository or install a reviewed version using
your normal software-provisioning process. Do not rely on an `npx -y ...@latest`
launch command: that can acquire executable code at startup.

Configure the resulting local executable as a stdio MCP server in the client
you choose. The exact configuration belongs to that client, not ScreenWise.

## authenticate to ScreenWise

The MCP process accepts the local bearer token from:

```text
SCREENPIPE_LOCAL_API_KEY
```

Retrieve the token for the recorder's data directory with:

```powershell
screenpipe auth token --data-dir <recorder-data-directory>
```

Set that value in the MCP process environment. The package can also read the
local plaintext SQLite secret store when the `sqlite3` executable is explicitly
available. It never invokes a package manager to discover the token.

## verify the local dependency first

Before troubleshooting MCP, verify ScreenWise itself:

```powershell
curl.exe http://127.0.0.1:3030/health
curl.exe "http://127.0.0.1:3030/search?limit=1" `
  -H "Authorization: Bearer <local-token>"
```

If these calls work but MCP does not, check the MCP client's executable path,
environment block, and stdio logs.

## security boundary

The ScreenWise API is loopback-only by default and bearer authentication must
remain enabled. An MCP client receives access to recorded screen and audio data,
so provision only clients you trust. ScreenWise does not provide a hosted MCP
relay or cloud-synced data source.
