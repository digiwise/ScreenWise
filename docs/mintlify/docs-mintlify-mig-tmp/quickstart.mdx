ScreenWise does not acquire tools or models from the Internet. Provision and
verify every required artifact before switching on the feature that uses it.

## prerequisites

- Windows screen-recording and accessibility permissions
- FFmpeg and FFprobe on `PATH` for local audio workflows
- the pinned ONNX Runtime DLL expected by the build
- explicitly provisioned local transcription models
- optionally, verified ONNX PII models for semantic redaction
- optionally, a reviewed pinned-version Pi runtime and a locally running Ollama service

The repository's `BUILD_NOTES.md` records the expected versions, locations, and
checksums for the validated Windows build.

## start and verify

1. Start ScreenWise and select the monitors and audio devices to record.
2. Allow it to capture activity for a few minutes.
3. Verify the loopback service:

```powershell
curl.exe http://127.0.0.1:3030/health
```

4. Retrieve the bearer token for the same data directory:

```powershell
screenpipe auth token --data-dir <recorder-data-directory>
```

5. Search locally with that token:

```powershell
curl.exe "http://127.0.0.1:3030/search?limit=5" `
  -H "Authorization: Bearer <local-token>"
```

The bearer token protects recorded local data and is unrelated to AI-provider
credentials. ScreenWise has no product login or hosted-provider key.

## optional local AI

Provision Pi and Ollama separately, then select the native Ollama preset. See
[Ollama](/ollama). ScreenWise neither installs the runtime nor downloads a
model.

## optional MCP access

The MCP package is a separate local client of the authenticated loopback API.
Install or build it explicitly, then configure your chosen MCP host manually.
See [MCP server setup](/mcp-server).
