ScreenWise is built and validated as a Windows-first local recorder. Use a
reviewed desktop or CLI build supplied through your normal software-provisioning
process. The application does not check for updates or download missing runtime
components.

## choose an interface

| interface | use it for |
| --- | --- |
| desktop | recorder settings, timeline, local search, and optional local Ollama chat |
| CLI | terminal-managed recording and authenticated loopback API access |

Before launch, provision FFmpeg and the selected local audio, transcription,
and PII models. See `BUILD_NOTES.md` in the source repository for the validated
Windows prerequisites and checksums.

## verify the recorder

Once ScreenWise starts, confirm the loopback service is healthy:

```powershell
curl.exe http://127.0.0.1:3030/health
```

Protected endpoints require the token associated with the recorder data
directory:

```powershell
$token = screenpipe auth token --data-dir <recorder-data-directory>
curl.exe "http://127.0.0.1:3030/search?limit=5" `
  -H "Authorization: Bearer $token"
```

Do not disable local API authentication. The token is stored locally and is
independent of optional Ollama configuration.

## optional local consumers

- [Ollama](/ollama) describes the fixed local chat endpoint.
- [MCP server setup](/mcp-server) describes manually provisioning a local MCP
  client for the authenticated API.
- [API recipes](/api-recipes) provides direct loopback queries.

ScreenWise does not configure third-party services or acquire packages on their
behalf.
